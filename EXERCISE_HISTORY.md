# Exercise History Documentation

## Overview

The Exercise History feature tracks all sentences generated by the AI for both student exercises and teacher examples. This provides users with a comprehensive history of their learning materials, allowing them to review previously generated content and filter by various criteria.

## Key Features

### 1. Automatic Saving

- **When**: Sentences are automatically saved immediately after AI generation
- **Where**: Saved to `SentenceHistory` collection in MongoDB
- **What**: Each sentence is stored with metadata including:
  - The sentence text (without hints for exercises)
  - Language ID
  - Proficiency level (A1, A2, B1, B2, C1, C2)
  - Used word IDs (words that were used to generate the sentence)
  - Generation mode (student/teacher)
  - Owner ID (user who generated it)
  - Creation timestamp

### 2. Filtering System

The history page provides three types of filters:

#### Text Search Filter

- **Type**: Case-insensitive text search
- **Scope**: Searches within sentence content
- **Implementation**: Uses MongoDB's case-insensitive regex matching
- **Note**: No separate word filter is needed - text search is sufficient for finding specific words

#### Language Filter

- **Type**: Dropdown selection
- **Options**: All available languages (English, Polish, etc.)
- **Default**: "All languages" (no filter)
- **Purpose**: Filter sentences by target language

#### Level Filter

- **Type**: Dropdown selection
- **Options**: A1, A2, B1, B2, C1, C2
- **Default**: "All levels" (no filter)
- **Purpose**: Filter by proficiency level

### 3. Pagination Support

The UI is designed with pagination in mind:

- **Current State**: Displays all results at once
- **Future Enhancement**: Pagination will be implemented to handle large datasets
- **Backend Ready**: Repository methods support pagination parameters

### 4. Sentence Format Specifications

#### Generated Format (Bold Format)

Sentences are generated with the key word highlighted using bold markdown:

```
They **visited** many countries last summer. (visit)
She **bought** a beautiful dress yesterday. (buy)
I need **a** new phone.
```

#### Storage Format

When saving to history, hints (parentheses content) are removed:

```
They **visited** many countries last summer.
She **bought** a beautiful dress yesterday.
I need **a** new phone.
```

#### Display Format

The UI component `LearnModeText` handles both formats:

1. **Bold format** (primary): `**word**` → Displays as blank/input field
2. **Legacy placeholder format**: `{{input}}` → Also supported for backward compatibility

#### Format Rules

- **Student Mode**: Generates 5 sentences with hints when appropriate
  - Hints provided for: verb infinitives, base noun forms
  - No hints for: articles (a/the), "to be" in continuous tenses
- **Teacher Mode**: Generates 10 sentences without hints
  - All sentences in correct grammatical form
  - No hints needed (for learning, not practice)
- **Consistency**: Both modes use the same bold format for simplicity

## Technical Implementation

### Database Schema

```prisma
model SentenceHistory {
  id          String   @id @default(auto()) @map("_id") @db.ObjectId
  sentence    String
  languageId  String   @db.ObjectId
  usedWordIds String[] @db.ObjectId
  level       String
  mode        String   @default("exercise") // "student" or "teacher"
  ownerId     String   @db.ObjectId
  createdAt   DateTime @default(now())

  owner    User     @relation(fields: [ownerId], references: [id], onDelete: Cascade)
  language Language @relation(fields: [languageId], references: [id], onDelete: Cascade)
}
```

### Repository Layer

**File**: `src/repository/SentenceHistoryRepository.ts`

#### Key Methods

1. **addHistory** - Add single sentence

```typescript
async addHistory({
  ownerId,
  sentence,
  languageId,
  usedWordIds,
  level,
  mode = 'exercise'
})
```

2. **addHistoryBatch** - Add multiple sentences (used after generation)

```typescript
async addHistoryBatch(sentences[])
```

3. **getHistory** - Retrieve filtered history

```typescript
async getHistory({
  ownerId,
  languageId?,
  level?,
  usedWordIds?,
  searchText?
})
```

**Filtering Logic**:

- `languageId`: Exact match
- `level`: Exact match
- `usedWordIds`: MongoDB `hasSome` operator (matches if any word ID is present)
- `searchText`: Case-insensitive contains search (`mode: 'insensitive'`)

### Service Layer

**File**: `src/services/generatedHistoryService.ts`

Simple wrapper around repository:

```typescript
export async function getGeneratedHistoryService(
  userId: string,

```

**File**: `src/services/generateTextService.ts`

Contains the logic for saving generated sentences:

- Extracts words from bold format (`**word**`)
- Removes hints from sentences before saving
- Maps selected words to their IDs
- Saves batch after successful generation

## Usage Flow

### 1. Generation Flow

```
User selects topic, language, level, words
    ↓
Clicks "Generate" button
    ↓
POST /api/ai/generate-text
    ↓
AI generates sentences
    ↓
Format sentences (parse bold words, remove hints)
    ↓
Save to SentenceHistory (batch insert)
    ↓
Return sentences to user
```

### 2. History Viewing Flow

```
User navigates to History page
    ↓
Fetches languages and levels
    ↓
Loads initial history (no filters)
    ↓
User applies filters
    ↓
Clicks "Search" button
    ↓
GET /api/ai/generated-history?params
    ↓
Display filtered results
```

## AI Generation Prompts

**File**: `src/prompts/grammarPrompts.ts`

### Student Mode Prompt

- Generates 5 sentences
- Highlights ONE key word with `**word**`
- Adds hints in parentheses when appropriate
- Example: `They **visited** many countries last summer. (visit)`

### Teacher Mode Prompt

- Generates 10 sentences
- Highlights ONE key word with `**word**`
- NO hints (for learning/viewing only)
- Example: `They **visited** many countries last summer.`

**Key Requirements**:

- All sentences must be grammatically correct
- Highlighted word must be in CORRECT form (not base form)
- Sentences should demonstrate the grammar topic
- Level-appropriate vocabulary and structures

## Word Tracking

### Purpose

Track which dictionary words were used to generate each sentence.

### Implementation

1. User selects words from dictionary
2. During generation, AI uses these words
3. After generation, code extracts bold words from sentences
4. Matches extracted words to selected words (case-insensitive)
5. Stores matched word IDs in `usedWordIds` array

### Use Cases

- Filter history by specific words (future feature)
- Track word usage frequency
- Identify which words generate best exercises
- Link sentences back to dictionary

## Best Practices

### For Developers

1. **Always remove hints before saving**: Hints are for UI display only
2. **Use batch insert**: More efficient than individual saves
3. **Case-insensitive matching**: Always use for text search
4. **Include language relation**: Makes filtering more efficient
5. **Store mode**: Important for distinguishing exercise vs. learning content

### For AI Assistants

1. **Follow prompt format exactly**: Ensures consistent parsing
2. **One bold word per sentence**: Simplifies extraction logic
3. **Correct grammatical forms**: Highlighted word must be in correct form
4. **Level-appropriate content**: Match vocabulary to proficiency level
5. **Return only sentences**: No explanations or headers

## Troubleshooting

### Sentences not saving

- Check if AI generation succeeded
- Verify userId is valid
- Check database connection
- Look for errors in try-catch block in `generateTextService.ts`

### Filters not working

- Verify filter values are correctly formatted
- Check case-sensitivity (should be insensitive for text)
- Ensure languageId and level are valid values
- Test each filter independently

### Words not tracked

- Verify words are in selected words list
- Check bold format is correct (`**word**`)
- Ensure case-insensitive matching is working
- Look at extraction logic in `generateTextService.ts`
